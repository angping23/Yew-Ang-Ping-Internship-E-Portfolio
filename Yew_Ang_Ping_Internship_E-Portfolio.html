Smart Traffic Signal Optimisation at Changlun Intersection Using Discrete-Event Simulation

Changlun Intersection in Kedah is congested at peak hours because its fixed-time signals give each approach the same green time whatever the demand. I counted traffic by hand for seven consecutive mornings (7–9 a.m.), fitted vehicle arrival distributions in Arena Input Analyzer, and built a discrete-event simulation in Rockwell Arena 16.1. The model was verified and validated against the field counts. I then compared three signal strategies: the existing fixed-time signal, a manually reallocated green time, and a queue-length-based smart adaptive signal that gives green to the longest queue.

Role
Independent researcher: collected and analysed the traffic data, built and animated the Arena model, validated it, ran the what-if scenarios and wrote the report.
Skills / tools
  • Arena 16.1
  • Input Analyzer
  • Discrete-event simulation
  • What-if analysis
  • Data collection
  • Report writing
Outcome / impact
The adaptive signal gave the best overall result with throughput unchanged (6,434 vs 6,435 vehicles). North average waiting time fell from 55.19 to 39.15 seconds, East from 80.13 to 67.44 and West from 76.87 to 68.38. North queue length dropped from 14 to 10 vehicles. South waited slightly longer (45.03 to 52.26 seconds) because the controller favoured longer queues.
Reflection
I learned that a simulation is only useful once it is validated against real data. A big challenge was the animation: resource-based animation caused runtime errors, so I switched to variable-based signal control, and I had to loop the signal controller so it cycled continuously. This taught me to test small and trace errors to their cause. It connects to my goal of using data to support operational decisions.

Video Game Sales Dashboard: What Makes a Top-Selling Game?

This interactive Tableau dashboard asks what the secret formula behind a top-selling game is. It shows global sales by genre, platform and publisher in ranked bar charts, and a treemap of how these game features contribute to global sales. Users can filter by year and feature type and change a drill-down level to move from overview to detail. I used a dark, game-themed design so the story reads quickly and the highest-selling segments stand out.

Role
Dashboard developer: cleaned the data, chose the visuals, built the filters and drill-down, and designed the layout and story.
Skills / tools

Outcome / impact

Practicum project: Supplier Demand Automation

Before, each new weekly demand file meant repeating XLOOKUP matching, manual filtering and report saving. Now the user drops the latest file in a folder and clicks one button. Power Query selects the latest week, merges demand with the combined supplier mapping (left outer join on Item_Number) and splits it by supplier. VBA refreshes everything, exports WW48'26_APW / BPM / CST reports to an Output folder, keeps earlier weeks, and updates the dashboard. I tested it on a simulated dataset of 30 items across three suppliers (10 each), and all three reports generated correctly.

Next steps in my report: test with real company data and more suppliers, add scheduled runs, and add validation for unmatched or duplicate items.
